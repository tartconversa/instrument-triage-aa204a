# 共同工况下的仪表复核优先级：数据应用说明

本应用回答三个问题，并按"当时可知"回看：

1. **先查什么** —— 哪些证据单元可能改变能源判断，一次现场校验能同时澄清哪几个测点。
2. **为什么值得查** —— 能减少多少决策不确定性、要占用哪个窗口多少名额与预算。
3. **查完以后哪些判断才有依据** —— 现场结果确认或排除某个解释后，哪些单耗与归因随之更新，哪些结论仍不能安全形成。

产品只输出分析复核建议，不控制生产设备。数据全部为本地合成资料。

## 快速开始

```bash
python3 -m pip install -r requirements.txt
python3 -m steamcheck --summary                 # 文本摘要（资料最新可知时点）
python3 -m steamcheck --summary --as-of 2025-02-13T08:00:00+08:00
python3 -m steamcheck --json --write-state out.json
python3 -m steamcheck.serve --port 8765         # 本地只读网页视图
```

网页视图为单页，四张图 + 若干表格视图，全部数字来自同一份快照（`/api/snapshot`），
切换"当时可知"时点会整页重算，不在前端二次推断。

## 方法：为什么不是"每个测点一条控制线"

**单测点控制线在负荷切换当天会把 6 只表同时判为异常。** 资料在 2025-01-24 从
`normal` 切换到 `high`，原始读数整体抬升 20%–30%。若用切换前的中心与尺度去衡量，
切换日 6 只表全部越过 3 倍尺度，随后 18 个"多点同时异常"的日子全部是同一个运行原因。

应用的基线层因此做两件事：

1. **按运行档分别取中位数**（每个运行档最早 6 天作参考）。档位切换本身由档位中心吸收，
   不再进入残差。
2. **扣除共同负荷**：每天的"负荷比例"取各测点相对本档中心比值的中位数，并做一步
   截尾（偏离超过 2.5 倍尺度的测点先剔除再重估）。中位数对 1–2 个测点异常不敏感，
   截尾进一步避免一个极端读数把共同负荷整体带偏。被检验的变送器可以从负荷估计中
   剔除（`load_ratio(..., excluded=...)`），避免"被检验对象抬高自己的基准"。

剩下的是**个体残差**，才是仪表自己的证据。尺度用相邻日差分的稳健估计，对慢漂移稳健。

### 证据单元：一个变送器，不是一张表

同一变送器下的测点共享通道。残差先按变送器取平均形成合成分数，再做两类检测：

- **持续台阶**：前后两段**中位数**差（t ≥ 4，两段各至少 4 天）；用中位数而不是均值，
  单日尖峰不会被误判成持续偏移。起点再按"越过半幅"收回到真实第一天；
- **单日尖峰**：与前后各两天比较，且要求至少一个测点自身越过 3 倍尺度
  （避免两个测点的小幅反向波动被平均成尖峰）。

一个证据单元只生成一次现场任务。资料里 `M1`、`M2` 同属 `T1`，一次校验同时澄清两只表，
只占一个窗口名额——而不是两条独立告警。

## 本资料集上的结果

证据单元 `E1-T1-2025-01-31`：`high` 档内 2025-01-31 起，T1 下的 M1、M2 同时台阶
**+5.78 t**（两测点差异 0.02 t，远小于各自 1.5 t 左右的日常尺度）。同期 HP 边界守恒量
只变化 **+1.37 t**——约等于台阶的四分之一。

| 候选解释 | 判定 | 依据 |
| --- | --- | --- |
| 单日抽样波动 | 矛盾 | 持续 11 天、两个测点同向 |
| 变送器 T1 共享加法偏移 | **可能** | 同变送器两测点同向、同量（差异 0.02 t）；单表故障不能同时解释 |
| M1 单表偏移 / M2 单表偏移 | 矛盾 | 另一测点同步移动，单表解释不足 |
| HP 真实用量再分配 | **可能** | 守恒量未同量变化，但供汽与用汽同步上升在读数上等价 |
| HP 未计量净流量（放空/泄漏） | **可能** | 需解释 1.37 t，在资料允许的 ±45 t 区间内 |
| 已确认放空 N1（5 t） | 矛盾 | 生效于 2025-01-26，不在证据窗口内；单次放空不能解释持续台阶 |

**没有指定唯一故障。** 三条可能解释保留到现场结果或运行记录补充为止。

### 数值异常 vs 改变决定

- HP 单耗 **1.449**，决策上限 **1.12**，属于"高于上限"。
- 若供汽表偏移成立，单耗约为 **1.385**——仍然高于上限。
- 所以 **阈值判断不随解释改变**；会改变的是**归因**（修正计量 / 按运行变化操作或排查损失），
  按 `wrong_decision_cost`（HP 12000 元）计价。
- LP 在证据窗口内没有超阈残差，单耗 1.244 高于 0.95 属于运行事实，不是仪表故事。

界面把这两类拆成"数值异常但不改变决定"和"可能改变决定但证据不足"两栏，并明确写出
"阈值判断不变、改变的是归因"。

## 复核安排：组合，不是逐条贪心

- 价值 = 有分歧的可行解释对应的错误决定代价 × 0.5（**等权假设**，资料未给概率）− 现场代价。
- 价值按**覆盖证据单元的并集**计算一次：`I1`（T1/W1/1800 元/精度 0.4）与 `I4`（T1/W2/1500 元/精度 0.6）
  覆盖同一变送器，互为替代而不是两个任务；按精度优先选 `I1`，并在理由中写明与 `I4` 的比较。
- 窗口按容量与预算分别约束；同一窗口内枚举可行组合（选项很少，穷举），取价值最高者。
- **已完成的检查与占用的窗口不释放**；`undone` 也消耗已实际使用的窗口与费用，但不提供合格证据。

### 预算不足时

把某个窗口预算压到买不起任何检查时，应用不会把未执行的告警默认为正常，而是输出
"剩余窗口的名额/预算不足以区分关键解释：E1-… 的相关结论仍不能安全形成"。

## 现场结果之后

示例资料登记了两个结果：

- `R1`（I1，2025-02-13 可知）：`shift 5.8 t` → 与读数台阶同向同量级，**共享偏移获得支持**；
  HP 单耗由 1.449 修正为 1.385（结论仍是"高于上限"）。
- `R2`（I3，2025-02-14 可知）：`undone` → 不提供合格证据；窗口 W2 与 1600 元费用已占用，
  不能改派其他变送器。

`R2` 不会覆盖 `R1` 已澄清的结论（这是应用里专门测试过的状态机行为）。切换时点即可回看：
在 2025-02-12 时，W1/W2 都还空着，`R1` 尚不可知；在 2025-02-13 之后才会出现修正后的单耗。

## 时间与证据口径

- `effective_at` 与 `known_at` 严格分离。观测、换表、放空/检修、现场结果都按 `known_at` 进入时间线。
- 事后确认的运行记录（如 N1 到 2025-02-04 才可知）**不能**用来解释更早时点"当时是否应告警"。
  应用在 2025-02-03 的时点还看不到 N1。
- `inspection_options.status = planned` 只是候选清单状态，不等于已排产，不占名额；
  占用名额的是已经发生的现场结果（`completed` 或 `undone`）。
- 换表后使用新量程与新误差界；`contracts_at()` 按 `effective_at` 切换，历史记录仍保留原表号。
- 采样频率不同：M1/M2 每日两次、其他每日一次。先按日求均值，再让每日等权，联合比较不重复计入。

## 代码结构

| 模块 | 职责 |
| --- | --- |
| `steamcheck/sources.py` | 读取资料、跨表一致性检查、换表契约、按 known_at 过滤的事件时间线 |
| `steamcheck/anomaly.py` | 档位基线、共同负荷、残差、变送器级证据单元、候选解释集合 |
| `steamcheck/decisions.py` | 单耗与决策界限、修正值、阈值不变性、归因分歧、清晰度分组 |
| `steamcheck/inspection.py` | 窗口占用、现场结果解释、候选排序与组合选择、覆盖摘要 |
| `steamcheck/engine.py` | 组装一次快照（含 `as_of` 可选时点、caveats） |
| `steamcheck/cli.py` / `serve.py` | 文本摘要 + 本地只读网页视图 |
| `steamcheck/web/*` | 无构建步骤的 SVG 图表与表格视图 |

## 已知局限

- 价值用"等权假设"，不是概率推断；界面与排序理由都标注了这一点。若要换成概率，需要额外的
  先验，资料没有提供。
- 共同负荷用比值中位数，近似线性响应；若负荷与测点之间明显非线性，残差会保留一部分负荷影响，
  应改为分档回归。
- 证据阈值（t ≥ 4、3 倍尺度等）是稳健性选择，不是统计显著性的严格结论；阈值附近的证据单元应
  按"证据不足"处理。
- 未计量净流量区间按 `flow_boundary` 的 `unknown_max` 求和作为包络；没有把检修/放空记录从区间中扣除。
